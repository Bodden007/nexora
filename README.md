## 3. Назначение NEXORA

NEXORA — кроссплатформенный промышленный программный шлюз (Industrial Data Gateway).

Приложение устанавливается на промышленном ПК и пассивно получает копию потока данных, передаваемого от промышленного оборудования в систему iCem.

Поддерживаются два альтернативных источника:

### National Instruments Compact cRIO

- Ethernet IEEE 802.3 LLC.
- Перехват через зеркальный порт управляемого Ethernet-коммутатора (SPAN).
- Приём Ethernet-кадров без необходимости назначения IP-адреса для самого LLC-трафика.

### FLECS

- RS-232 ASCII.
- Сообщения в формате CSV.
- Приём через аппаратный пассивный отвод последовательной линии.
- Параметры последовательного соединения и сигнатура сообщений известны.

На конкретной установке предполагается один рабочий исходный поток.

> ⚠️ NEXORA не должна вмешиваться в существующий обмен оборудования с iCem, передавать команды или изменять работу исходных устройств.

## 4. Итоговая схема работы

```
NI Compact cRIO ── Ethernet LLC ──┐
                                  │
                                  ├── Пассивный перехват
                                  │
FLECS ─────────── RS-232 ASCII ───┘
                                  │
                                  ▼
                                NEXORA
                                  │
                         Идентификация потока
                                  │
                          Приём и декодирование
                                  │
                        Технологические значения
                                  │
                        Modbus TCP Server
                                  │
                                  ▼
                           ОВЕН ПЛК210
                        Modbus TCP Client
```

Источники NI cRIO и FLECS — альтернативные. Штатный канал передачи данных в iCem сохраняется независимо от NEXORA.

## 5. Modbus TCP — согласованное решение

- **NEXORA** — Modbus TCP Server (Slave).
- **ОВЕН ПЛК210** — Modbus TCP Client (Master).

ПЛК210 самостоятельно инициирует Modbus TCP-запросы и считывает подготовленные значения из регистров NEXORA.

NEXORA:

- Принимает исходные данные.
- Декодирует технологические параметры.
- Обновляет карту Modbus-регистров.
- Обслуживает запросы ПЛК210.
- Предоставляет информацию о достоверности и актуальности данных.

> ⚠️ NEXORA не инициирует Modbus-запросы к ПЛК210.

Карта регистров, типы данных, порядок байтов, поддерживаемые функции и период опроса согласовываются на отдельном этапе.

> ⚠️ Не реализовывать Modbus TCP до согласования соответствующего этапа.

## 6. Конфигурация промышленного ПК

NEXORA должна использовать внешний конфигурационный файл — `nexora.toml`.

- Файл располагается рядом с исполняемым приложением, независимо от текущего рабочего каталога процесса.
- Конфигурация содержит необходимые настройки интерфейсов и режимов работы.
- Не зашивать настройки конкретного промышленного ПК в исходный код.

### 6.1. Режим первоначальной настройки

Команда:

```bash
nexora --conf
```

Программа должна:

1. Определить доступные Ethernet-интерфейсы.
2. Определить доступные последовательные порты.
3. Показать обнаруженные интерфейсы в консоли.
4. Предоставить выбор интерфейсов по номеру.
5. Предоставить тестовый просмотр ASCII-потока.
6. Проверить выбранные настройки.
7. Сформировать `nexora.toml`.
8. Сохранить файл после подтверждения пользователя.

При повторном запуске `--conf` необходимо показывать текущие настройки и позволять их изменить.

> ⚠️ Не требовать ручного редактирования TOML для стандартной первоначальной настройки.

### 6.2. Тестовый просмотр ASCII

После выбора последовательного порта пользователь может запустить тест.

В тестовом режиме необходимо:

- Открыть выбранный COM-порт с заданными параметрами.
- Отображать реальные входящие ASCII-сообщения.
- Проверять сигнатуру FLECS.
- Проверять корректность структуры CSV.
- Показывать количество принятых сообщений и диагностические ошибки.
- Позволять остановить тест и вернуться к настройке.
- Не передавать данные в RS-232.
- Не подменять отсутствие данных искусственно сформированными сообщениями.

Тестовый режим не должен изменять состояние штатной рабочей сессии.

Проверка реального потока предпочтительна перед сохранением конфигурации. Если оборудование не запущено, допускается сохранение с явным предупреждением о неподтверждённом источнике.

### 6.3. Штатный запуск

Команда:

```bash
nexora
```

Программа должна:

1. Найти `nexora.toml` рядом с исполняемым файлом.
2. Загрузить настройки.
3. Проверить их корректность.
4. Инициализировать разрешённые интерфейсы.
5. Перейти к обнаружению рабочего потока.

Штатный запуск не должен требовать участия оператора.

> ⚠️ Отсутствующая или некорректная конфигурация — диагностируемая ошибка.

Изменения настроек применяются после перезапуска приложения.

## 7. Обнаружение источника

При запуске допускается параллельное прослушивание Ethernet LLC и RS-232 ASCII. Для идентификации используются признаки конкретного оборудования.

**LLC:**

- Структура IEEE 802.3 LLC.
- Характерные поля и сигнатура пакетов.
- Подтверждение по нескольким последовательным сообщениям.

**ASCII:**

- Известные параметры последовательного порта.
- Известная сигнатура FLECS.
- Корректная структура CSV.
- Подтверждение по нескольким сообщениям.

> ⚠️ Наличие произвольного Ethernet-трафика или ASCII-символов не является подтверждением нужного источника.

### Приоритет

При одновременном подтверждении двух источников выбирается RS-232 ASCII (FLECS).

Необходимо исключить гонку между параллельными процедурами обнаружения. Механизм приоритета должен быть детерминированным.

> ⚠️ Не создавать для этого избыточную систему управления состояниями.

### Фиксация источника

После выбора:

- Тип источника фиксируется до завершения процесса.
- Неиспользуемые интерфейсы освобождаются.
- Переключение на другой протокол запрещено.
- При потере потока приложение ожидает восстановления выбранного источника.
- При восстановлении продолжает приём на том же интерфейсе.
- Повторное определение источника допускается только после перезапуска приложения.

**Принцип:** `Initialize Once → Receive → Wait → Resume`

> ⚠️ Учитывать, что оборудование может начать передавать данные значительно позже запуска NEXORA.

## 8. Обработка данных

NEXORA должна преобразовывать исходные сообщения LLC или FLECS ASCII в технологические значения, предназначенные для ПЛК210.

Необходимо обеспечить:

- Проверку корректности сообщений.
- Декодирование только подтверждённых полей.
- Преобразование значений в согласованные типы данных.
- Обновление Modbus-регистров.
- Диагностику отсутствия и недостоверности данных.

> ⚠️ Не придумывать структуру протокола, назначение полей, коэффициенты преобразования и карту регистров.

Неизвестные параметры устанавливаются путём анализа реальных данных и отдельного согласования.

Для LLC имеются реальные образцы перехваченных Ethernet-пакетов. Использовать их как материал для исследования, а не считать все предварительные гипотезы доказанными.

## 9. Надёжность

Приложение рассчитано на длительную непрерывную эксплуатацию.

Предусмотреть корректное поведение при:

- Отсутствии данных после запуска.
- Временной остановке передачи.
- Перезапуске исходного оборудования.
- Неполных или повреждённых сообщениях.
- Недоступности интерфейсов.
- Ошибках открытия портов.
- Отсутствии прав для Ethernet-захвата.
- Некорректной конфигурации.
- Ошибках сетевого взаимодействия с Modbus TCP Client.

> ⚠️ Не создавать циклы интенсивного опроса без необходимости.  
> ⚠️ Не допускать бесконтрольного накопления данных в памяти.

При потере источника устаревшие значения не должны представляться ПЛК как достоверные. Способ сигнализации недостоверности согласовать вместе с картой Modbus-регистров.

## 10. Кроссплатформенность

NEXORA разрабатывается на Rust для Windows и Linux.

- Основная логика и формат конфигурации должны быть общими.
- Платформозависимые участки допустимы только там, где необходимы для работы с оборудованием и системными интерфейсами.
- Для разных ОС и архитектур процессоров допускаются отдельные бинарные сборки.
- Конфигурация конкретного ПК не требует перекомпиляции.

> ⚠️ Не создавать отдельные архитектуры для Windows и Linux.
